## Fluxo de trabalho: hooks, conflitos e revisão (estratégia de desenvolvimento, 05/11/2026)

- **Os hooks do `.claude/settings.json` podem não rodar nas threads da nuvem.** Sintoma: `Read` do `package-lock.json` inteiro passa (o `guarda` devia barrar), `git commit` não roda o check e nenhum `.claude/tmp/check.txt` aparece. Causa: a thread da nuvem do claude.ai não executou os hooks do projeto em 05/11/2026 (em 20/10 uma sessão da nuvem os executou: não dá para contar com nenhum dos dois); o plugin claude-mem também não chegava a instalar (saiu do `settings.json`). Solução: nas threads da nuvem, `npm run check` à mão antes de tirar do rascunho; os portões que valem são os do GitHub (proteção de branch, `verificar`, `e2e`, `guarda`). Não conte com hook para regra que precisa valer na nuvem: ponha num script (`npm run ...`) e no `AGENTS.md`.
- **PR "dirty" no GitHub, mas o `git merge` local passa limpo.** Causa: o `merge=union` do `.gitattributes` vale para o git local; o botão e o cálculo de conflito do GitHub o ignoram. Solução: entrada nova de registro em `docs/entradas/` (nunca no fim do registro), e só então não há o que unir. Para medir como o GitHub vê: `node scripts/medir-merges.mjs <data>` (usa `git --attr-source <árvore vazia> merge-tree`; `-c core.attributesFile` não basta, porque o `.gitattributes` do repositório tem precedência).
- **Branch atrás da integracao não é motivo para trazê-la.** A proteção da `integracao` não exige branch atualizado (o #436 estava atrás e `clean`). Trazer só com conflito (`dirty`) ou dependência.
- **Continuar no branch depois do merge do PR.** `git fetch origin integracao && git merge --ff-only origin/integracao`: o branch é ancestral da integracao, então é avanço simples, sem force push. Se o `--ff-only` recusar, há commit local fora do PR: confira antes de seguir.
- **Revisão de tela sobre SHA velho (#424).** Solução: o revisor escreve o SHA; antes do merge, `npm run revisao:cobre -- <sha> origin/<branch>` diz se mudou tela depois. Só conta arquivo do próprio PR (o que veio da integracao não pede revisão nova).
